This repository contains no executable code, so there is no software vulnerability to report in the usual sense.

## 🚨 Report these privately, not in an issue

**Real data has appeared here.** If you believe anything in this repository contains a real personal record, a real customer or client identity, a genuine production schema, an internal system name, or anything else that should not be public, report it privately and immediately.

**A credential has appeared here.** An API key, token, password or connection string, whether in a file, a commit message or the repository history.

## 📮 How to report

Email **NeumannTechTips@pm.me** with the file path and, if you can, the commit. Do not open a public issue, because doing so draws attention to exactly the content that needs removing.

Alternatively, use GitHub's [private vulnerability reporting](../../security/advisories/new) on this repository.

## ⏱️ What happens next

| When | What |
| --- | --- |
| Within 48 hours | Acknowledgement that the report has been received |
| Immediately on confirmation | The content is removed from the current files |
| As soon as practical | The history is rewritten or the repository is rebuilt, since deleting a file does not remove it from earlier commits |
| Where a credential was exposed | It is treated as compromised and rotated, whether or not there is evidence of use |
| Afterwards | A note in the commit history recording that a removal took place, without repeating what was removed |

Reporters are credited if they wish, and never named without being asked.

---

## 🧾 What is not in scope

Broken links, typographical errors, a query that fails on your database, or a prompt that behaves differently from the file. Those are ordinary [issues](../../issues) and the templates exist for them.
